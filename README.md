# ai-dev-standards

用于未来软件开发项目的 AI 开发规范与约束。按独立主题逐步扩展，每条规范保留唯一正文。

## 规范目录

| 编号 | 规范 | 状态 |
| --- | --- | --- |
| 001 | [项目地图与增量上下文规范](standards/001-project-map.md) | 已采纳 |
| 002 | [持久记忆与会话恢复规范](standards/002-persistent-memory.md) | 已采纳 |

001：通过地图定位上下文，检查有效性、按需读取真实代码并增量同步；首次理解项目时同时识别编码风格，新增功能沿用目标模块惯例。

002：在环境中保存需求、决策原因、任务状态及适用习惯；新会话恢复核心记忆，按任务读取历史，核验 Git 身份来源并区分团队变更归属。

## AI 阅读入口

从 [AGENTS.md](AGENTS.md) 开始，读取[记忆索引](.ai/memory/index.md)、[当前状态](.ai/memory/active.md)、[共享偏好](.ai/memory/preferences.md)和[项目地图](.ai/project-map.md)，核验当前代码状态后按需展开。

## 接入软件项目

1. 将适用规范保存到目标项目，例如 docs/ai-standards/，保留来源及所采用的版本。
2. 在目标项目所用 AI 工具支持的规则入口中显式引用规范、地图及核心记忆，并确认实际加载。
3. 按目标项目建立 .ai/project-map.md 与 .ai/memory/；识别模块风格，区分团队共享约定和个人偏好。
4. 读取当前仓库有效 Git 身份并标明来源，不把当前配置或提交署名当作真实作者的充分证明。
5. 根据技术栈配置索引与校验，记录人工核验和覆盖限制，并以独立新会话演练验证恢复效果。

仅创建本仓库不会自动约束其他项目，规范更新需显式同步。记忆中的推送、合并习惯不替代当次授权。

## 扩展方式与当前能力

新规范放入 standards/NNN-topic.md，以三位递增编号添加，同步目录、地图和记忆。工具指南放 guides/，不占用规范编号。

当前是纯 Markdown 仓库，已建立地图与最小记忆文件，采用人工结构、链接及状态核验。没有业务代码、自动依赖索引、CI 或记忆服务；跨会话恢复和真实团队场景尚未实测。
