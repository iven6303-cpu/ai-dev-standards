# ai-dev-standards

## 一句话应用到你的项目

将下面的话发给目标项目中的 AI：

> 请按 https://github.com/iven6303-cpu/ai-dev-standards/blob/main/INSTALL.md 将这套规范应用到当前项目。本地已有规范优先，不覆盖本地内容；启用每 7 天一次的会话启动更新检查，兼容更新按协议同步，有冲突保留本地并报告。

AI 首先阅读 [自动接入与更新协议](INSTALL.md)，固定实际采用提交、单独保存上游副本，增量连接本地入口，建立该项目自己的地图与记忆。不要把本仓库的地图、记忆或 AGENTS.md 原样覆盖到目标项目。

默认只在新会话且超过间隔时检查；没有新会话就不会后台运行。需要每周后台检查或更新 PR 时，另行按协议配置并验证调度权限。私有仓库需要目标 AI 已有访问权限，链接本身不授予访问。当前提供协议说明，未内置自动安装/更新程序，也未部署后台调度。

用于软件项目的 AI 开发规范与约束，按主题逐步扩展，每条规范保留唯一正文。

## AI 阅读入口

从 [AGENTS.md](AGENTS.md) 开始，按 000 明确主管责任；读取[记忆索引](.ai/memory/index.md)、[当前状态](.ai/memory/active.md)、[共享偏好](.ai/memory/preferences.md)及[项目地图](.ai/project-map.md)，核验当前事实。主管完整读取 001/002/003；子 AI 读取自身任务适用条款和必要上下文，不重复全仓扫描。

## 三层接入方式

1. 规则与记忆：将适用规范保存到目标仓库并保留来源、版本；建立地图和记忆，登记 Ponytail 固定版本及补充条款。
2. 加载与调度：按宿主实际支持的规则入口、skill、hook 和子代理接口接入；验证启动、恢复、角色约束继承、模式与文件隔离，避免重复注入。
3. 自动验证：接入格式、lint、类型、测试及主管证据核验；需要时配置 CI 必需检查、分支保护及审查权限并验证阻断效果。

MD 不会自行创建真实子 AI，也不保证规则已加载或执行；宿主不支持时明确降级。项目规则不覆盖更高优先级指令或权限，记忆中的提交合并习惯不替代当次授权。

新规范放 standards/NNN-topic.md；指南放 guides/。同步目录、地图、入口及受影响记忆，保留既有编号。

当前是纯 Markdown 仓库，已建立 000–003 四条规范、两份指南、地图和核心记忆，采用人工结构、链接与状态核验。尚未部署自动多代理调度、Ponytail、CodeGraph、hook 加载、CI 或合并门禁；真实软件任务、新会话和团队协作演练待验证。


## 分工与编码原则补充

000 采用影响范围、专业跨度、不确定性、风险及依赖关系五维判断，选择单 AI、专业复核或多专业实施；任务数量与步骤数仅作重评提示，旧 5/10 自动触发规则已废止。

003 第 8 节整合 Karpathy 的先思考、简洁优先、精准修改及目标驱动思想，保留 Ponytail 基础，不再叠加重复全文；明确合理假设、完整需求、必要联动和有边界验证，避免与已有规范冲突。参考社区 [andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills)，并非 Karpathy 本人官方发布的 skill。


## 维护与审查边界

启动顺序由 AGENTS.md 统一，各规范内部是对应子流程；同会话未变上下文可复用。当前记忆只保留有效状态，旧决定按需归档。任务实施、验证、提交及发布状态分别核验；文档采纳、工具接入和运行验收不混为一谈。规则和指南存在冲突时按适用范围与明确例外处理，不以模型自报作为生效证据。
