# CodeGraph 可选接入指南

关联规范：[001 项目地图与增量上下文规范](../standards/001-project-map.md)。本文是工具实现指南，不是第二条规范，也不将 CodeGraph 设为强制依赖。

状态：候选工具，待真实软件项目试点。文档依据 2026-10-17 查看到的上游说明；尚未安装、实测或接入本仓库，性能与覆盖率不作保证。

## 1. 适用范围与职责

适用于需要频繁查询符号、调用链和影响范围，且语言及框架受到工具支持的软件项目。纯文档项目、小型脚本或支持不完整的项目可继续使用人工地图和定向搜索。

- AGENTS.md：规定阅读与执行流程。
- .ai/project-map.md 和按需建立的模块地图：维护业务职责、架构边界、设计理由、数据归属、验证入口。
- .codegraph/：CodeGraph 维护本地代码图谱，提供结构、符号与依赖检索。

采用 CodeGraph 的范围内，通常无需另建重复的 dependencies.json；在项目地图声明索引提供者、实际覆盖范围和例外。工具不能取代语义地图、真实源码确认或测试。

## 2. 试点接入步骤

1. 选择一个真实项目，记录当前基线、语言与框架、代码规模、工具版本、解析限制和排除范围。
2. 参考上游安装说明选择并固定经评估的版本；安装前审阅配置作用域和将写入的 AI 指令。优先项目级配置，避免无意修改所有项目的工作规则或扩大权限。
3. 如需接入 AI，配置其支持的 MCP 服务；安装 CLI 本身不代表 AI 已连接。上游提供 codegraph install --print-config codex 用于查看配置片段；具体工具支持以当前版本为准。
4. 在目标软件项目目录执行 codegraph init 建立索引；核验 codegraph status、抽样关系和排除项，再开始使用。
5. 按项目隐私要求配置遥测；需要关闭时使用 codegraph telemetry off，或为运行进程设置 CODEGRAPH_TELEMETRY=0。索引本地存储不等于整个工具无网络通信。
6. 在目标项目地图登记安装版本、配置位置、实际验证命令、支持范围及降级方式。升级后复核兼容性与试点结果。

常用命令示例（接入时先检查已安装版本的 help）：

~~~sh
codegraph init
codegraph status
codegraph sync
codegraph query UserService
codegraph callers UserService
codegraph callees UserService
codegraph impact UserService
codegraph explore "指定文件或符号的调用流程"
~~~

查询应使用明确文件、符号或模块限制范围；歧义名称先定位，再分析。MCP 默认暴露的工具与 CLI 命令可能不同，必须按实际可用接口操作。

## 3. AI 执行约束

1. 先读项目地图，检查当前分支、提交及未提交改动，再查询有关代码图谱。
2. 检查同步状态和响应中的过期或待同步提示；监听不可用、批量变更或切换分支后，必要时执行 sync 并复查状态。自动监听不是永远新鲜的证明。
3. 按任务获取必要源码与关系，避免全图导出、宽泛探索和重复返回相同代码。结果不足时逐步扩大范围。
4. 修改前确认将改动的真实源码。工具返回的源码在路径、版本及同步状态已确认时可以复用；出现过期提示、内容矛盾、覆盖缺口或高风险修改时，直接读取受影响文件及必要调用方。
5. 推测关系、动态调用、配置注册和跨服务关系必须记录限制；查不到调用方不等于不存在调用方。影响分析只能辅助确定测试范围，不能单独证明安全。
6. 修改后确认图谱同步，并更新受影响的语义地图。CodeGraph 自动更新代码图谱，不会替 AI 完成职责、设计理由或业务边界的维护。
7. 项目规则优先于工具附带的使用建议。审阅安装器写入的指令，不能因其鼓励信任结果而取消必要源码核验或覆盖检查。

## 4. 存储与验证边界

本地图谱属于可重建产物，通常将 .codegraph/ 排除出 Git；提交经核验且不含敏感信息的共享配置与接入说明。不得把数据库当作需要全文送入模型的地图文件。目录排除、语言及文件大小限制可能造成覆盖缺口，必须抽样确认。

上游提供 affected 等命令帮助发现受影响测试，但静态关系和测试命名识别存在限制；公共接口、权限或数据模型变更仍需按规范扩大验证。CI 使用时必须显式建立或同步索引，不假定开发机监听在 CI 中存在。

## 5. 试点评估与退出条件

在同一项目基线选取至少三类任务：定位入口与调用链、分析公共符号影响、编辑后查询新增或删除关系。对比原有地图加定向搜索与 CodeGraph 方案，保持任务、模型和正确性验收一致。

记录：答案正确性、已知关系漏检与误检、同步延迟、工具调用次数、输入输出及缓存 token、总费用、耗时、会话上下文占用。作者基准只作参考，不能推导本项目必然节省相同比例。

若关系覆盖不足、同步异常或上下文成本变高，缩小使用范围或停用，回退到真实文件搜索；保留工具无关的语义地图。只有真实任务验证通过后，才考虑将其设为目标项目默认工具。
